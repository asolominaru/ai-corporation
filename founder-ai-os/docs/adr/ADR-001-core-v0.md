# ADR-001. Ядро v0: локальный журнал поверх SQLite, без новых зависимостей

Статус: принято. Дата: 2026-11-02.

## Контекст

Blueprint v1 описывает целевую систему (n8n → Temporal, PostgreSQL, два сервера, workers). Для этапа 0 нужен проверяемый фундамент без внешних сервисов и расходов. Преемственное решение — `10_corporation_repo/docs/adr/ADR-001-base-and-storage.md`: Node + node:sqlite, один writer, один хост.

## Решение

1. Стек: Node.js ≥ 22.13, `node:sqlite` (WAL), без npm-зависимостей.
2. Компания описывается конфигурацией (`config/`, `org/`, `blueprints/`) — «компания как код» с первого дня.
3. Журнал: протокол задач v1 + цикл ready → running → review → accepted / changes_requested; human approval как отдельный статус pending_owner.
4. Приёмка по sha256 артефакта; устаревшее решение и подмена копии отклоняются.
5. Переход к PostgreSQL/n8n/workers — этапы 1–2 дорожной карты, при появлении бюджета и подтверждённого RU-сервера.

## Последствия

- Не заявляем multi-user, RLS, кластер, автономное исполнение.
- История совместима по духу с workboard, но схема новая: автоматического переноса задач из corporation_repo нет; при необходимости — отдельная миграция с сохранением событий.
