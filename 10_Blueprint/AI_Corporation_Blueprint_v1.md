## 1. Что строим

Не «корпорацию Анастасии» как одноразовую конструкцию, а **AI Corporate OS** — универсальную систему управления компанией, где корпорация владельца является первым рабочим экземпляром (tenant). Позже ту же систему можно разворачивать другим компаниям как продукт.

**Компания как код**: Blueprint → Department → Agent → Skill → Workflow → Connector → Model. Конфигурация компании описывается файлами и переносится.

## 4. Департаменты и роли

Сохраняем существующий реестр 31 роли (A0–A14, E0–E8, S0–S3, P0–P1, F0). Поверх — новые функции:

**Content & Growth** (общий департамент, не отдельная корпорация): Content Director, Knowledge Miner, Researcher, Writer/Editor, Brand Voice, Distribution & Growth, Content Auditor. Каждый материал имеет поля BRAND / AUDIENCE / PURPOSE / FUNNEL_STAGE / CTA / PRODUCT / SOURCE / STATUS / RESULT. Редакционные потоки по брендам, деление по смыслам, не по соцсетям.

**Decision Science**: Chief Decision Scientist — формализует переменные, считает вероятности, строит симуляции, имеет право сказать «данных недостаточно для такого вывода». Инструменты: байесовское обновление гипотез, теория графов (для ВФОРУМЕ — продуктовая функция: ключевые участники, слабые связи, знакомства), имитационное моделирование решений до траты денег, согласование разногласий агентов («византийская задача»).

**Development**: Codex Worker + Claude Worker в связке. Режимы:
- `PAIR` — совместное проектирование архитектуры;
- `PARALLEL` — разные части одновременно (backend/frontend, отдельные worktree);
- `COMPETE` — независимые решения одной проблемы, выбирает аудитор;
- `REVIEW` — один пишет, другой проверяет (перед production — обязательно).

Над ними — AI CTO: кто выполняет, кто проверяет, когда merge, сколько попыток, когда спросить человека. Модели общаются только структурированными сообщениями, не свободным чатом.

## 5. Model Board и правила данных

| Класс задач | Назначение |
|---|---|
| Стратегия, архитектура | сильнейшая reasoning-модель |
| Кодинг | Codex + Claude Code (парно) |
| Независимый аудит, длинный контекст | третья модель, не автор кода |
| Тексты, UX, документация | средний класс |
| Классификация, квалификация лидов, массовая обработка | дешёвые модели |
| R&D-исследования | ансамбль + арена |

Правила: конфиденциальные и персональные данные — только в утверждённый контур; дешёвым и open-weight моделям — только обезличенные задачи; code review — не той моделью, что писала код; расход каждого запуска учитывается.

## 6. Инфраструктура: два узла

**KZ — AI Development Node** (VPS Beget kazakhstan, 91.218.140.48 — уже есть): Codex Worker, Claude Worker, оркестратор, n8n, Git, тестовая среда, учёт стоимости. Уже развёрнут read-only кабинет с журналом (26.10.2026).

**RU — Runtime / Production Node**: сайты, API, production-БД, бэкапы. Пользователь `deploy-ai` без root; деплой только через ограниченные sudo-команды (`deploy-<project>`); healthcheck и rollback обязательны. Существование и параметры RU-сервера **не подтверждены** — требуется решение владельца.

Связь: Tailscale/WireGuard, без открытого SSH наружу.

Цепочка поставки: задача → Codex → тесты → Claude review → staging → browser-тесты → human approval (для рискованного) → production → healthcheck → мониторинг. Авто-деплой только при tests PASS + review PASS + risk LOW.

## 7. Единый Task Protocol

```text
TASK_ID / PROJECT / GOAL / WHY / INPUT / EXPECTED_OUTPUT /
ACCEPTANCE_CRITERIA / TOOLS_ALLOWED / MODEL / MODE /
BUDGET / DEADLINE / OWNER / REVIEWER / HUMAN_APPROVAL / NEXT_ACTION
```

Запрещены задачи вида «изучи и предложи что-нибудь». Жизненный цикл: ready → running → review → accepted | changes_requested → running. Проверяющий принимает конкретную контрольную сумму артефакта; устаревшее решение отклоняется. Один агент не является сам себе заказчиком и контролёром.

## 8. Четыре воронки

1. **Внимание → деньги**: охват → интерес → контакт → квалификация → предложение → продажа → оплата.
2. **Клиент → результат → повторная продажа**: продажа → onboarding → измеримый результат → следующий продукт → продление → рекомендация.
3. **Контент-машина**: встречи/мысли → база знаний → сильные идеи → материалы → CTA → лид → CRM.
4. **R&D**: идея → исследование → гипотеза → MVP → разговоры с рынком → первые деньги → масштабирование / закрытие. Kill-критерий обязателен; правило: «сначала продажа, потом код».

## 9. Лестница монетизации (при минимальном капитале)

```text
ОБУЧЕНИЕ СОБСТВЕННИКОВ      деньги + лиды + customer discovery
        ↓
AI-ВНЕДРЕНИЕ КОМПАНИЯМ      высокие чеки сейчас; клиент финансирует разработку
        ↓                                    ↓
ВФОРУМЕ (вертикальный SaaS)      AI CORPORATE OS (будущий B2B-продукт)
```

Целевые чеки (гипотеза, не обещание): диагностика 150–300 тыс. ₽, архитектура 300–700 тыс. ₽, внедрение 700 тыс.–3 млн ₽, поддержка 100–500 тыс. ₽/мес. Модель ценообразования — движение к outcome-based (плата за результат, принцип Sierra). Продавать не «у нас есть ИИ», а закрытую работу: «ИИ полностью готовит форум-встречу».

ВФОРУМЕ позиционируется как **операционная система групп и сообществ** (принцип вертикальной глубины Harvey), не универсальный инструмент. Первая ценность — до обучения и внедрения (принцип Cursor): зарегистрировался → создал группу → через 5 минут получил работающую структуру встречи.

## 10. Что НЕ строим

- Собственную фундаментальную модель и GPU-инфраструктуру.
- Отдельную «корпорацию по контенту» и отделы по соцсетям.
- «ChatGPT с 40 агентами» до того, как работает производственный контур.
- Универсальный продукт «для всех» вместо вертикали.

## 12. Ограничения и честные оговорки

- Постоянного автоматического исполнителя пока нет: задачи выполняют агенты текущих сеансов; codex-worker/claude-worker как сервисы — этап 2.
- API-бюджет не задан (null в реестре) — платные автономные вызовы заблокированы до решения владельца.
- Цифры выручек референс-компаний и названия моделей взяты из исходного чата и не перепроверены.
- RU-сервер, домены/DNS, платёжные системы, API-ключи — зона действий человека; система их не требует и не запрашивает сама.
- Публикации, обращения к людям, расходы — только по отдельному поручению владельца.
