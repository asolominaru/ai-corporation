## 2. Закрыто в итерации 3 (п.3 и п.4 «Нового порядка работ»)

**П.3 — один серверный процесс обработки задачи:**

- Router — единственный путь к моделям: `services/orchestrator/app/modelclient.py`.
  Прямого вызова провайдеров в контуре оркестратора нет.
- Telegram сообщает решение по точной версии: мост
  `services/orchestrator/app/bridge.py` (TODO в `main.py` устранён).
  Approval → pending-запрос в реестре бота с `artifact_sha256` → кнопки
  владельцу → `POST /bridge/sync` переносит решение тем же атомарным
  conditional UPDATE. Решение применяется только от `decided_by ∈ OWNER_IDS`;
  решение после дедлайна превращается в expired.
- Файловая гонка реестра бота закрыта `fcntl.flock` (одинаковый протокол
  в `approval-bot/approvals.py` и `bridge.py`). Постоянная неисправность
  бота теперь видима: после 3 подряд сбоев poll — exit 1.
- Перезапуск приложения: состояние в SQLite-файле; E2E проверяет,
  что после dispose + нового приложения задачи, реестр, мост и аудит-цепь
  целы.
- Content-addressed хранилище артефактов: `artifact_text` в `report`
  проверяется по sha256 до записи; файл назван хешем.
