## 1. Что представляет собой проект

КОРПОРАЦИЯ — компания с ИИ-агентами и живыми специалистами. Владелец — Анастасия Соломина: задаёт цель, ограничения, выбирает направление, принимает промежуточный и конечный результат. Цифровой офис распределяет задачи, хранит материалы и версии, организует независимую проверку и возвращает результат на решение владельца.

Шесть направлений компании (решение владельца от 26.10.2026):

1. **Проявленность** (канал «Сила малых групп» входит в неё, не отдельное направление)
2. **ЯРДНИКИ**
3. **ВФОРУМЕ**
4. **Обучение ИИ**
5. **BrandFactory**
6. **Личная практика Анастасии Соломиной** (психоанализ, консультации, модерация, медиация; содержимое консультаций в общий архив не включается)

Владелец передал ссылку на переписку ChatGPT: https://chatgpt.com/share/6ae89b85-f874-83eb-af1f-d82cc28eb28d
Полный извлечённый текст сохранён: `01_Исходные_чаты/Организация команд и процессов__chatgpt_6ae89b85.txt` (87 сообщений; часть ответов ассистента в источнике скрыта как «redacted», картинка-схема не выгружена).

Дата чата не указана на странице; по содержанию он относится к периоду «октябрь 2026» и шире собранной ранее структуры: в нём обсуждаются **четыре контура (Я / Проявленность / Ярдники / ВФОРУМЕ) + R&D**, тогда как решением от 26.10.2026 утверждены шесть направлений. Это дополняющий, более стратегический слой — не замена текущего реестра направлений.

### Ключевые решения и идеи чата

1. **Одна AI-фабрика вместо пяти компаний**: владелец → AI-CEO/Дирижёр → бизнес-юниты + R&D → единый производственный контур → воронки → деньги → аналитика. Общие сервисы (маркетинг, финансы, юрист, аналитика, CRM) не дублируются по направлениям.
2. **Четыре связанные воронки**: внимание → деньги; клиент → результат → повторная продажа; контент-машина (сырьё → база знаний → материалы → CTA → лид → CRM); R&D (идея → MVP → первые деньги → масштабирование/закрытие, у каждой идеи kill-критерий).
3. **Единый производственный цикл**: сигнал → задача → исполнитель → результат → независимый аудитор → принято/переделать. Один агент никогда не является сам себе заказчиком и контролёром. CEO Dashboard с 3–7 вопросами «что требует решения Анастасии».
4. **Техническая архитектура Founder AI OS**: n8n как первый оркестратор (Temporal — позже для долгих процессов), PostgreSQL/Supabase как операционная память, Google Drive как человеческая память, Git как память разработки; единый TASK PROTOCOL (цель, вход, результат, критерии, исполнитель, проверяющий, бюджет, human approval); Model Router; учёт стоимости моделей.
5. **Готовые ТЗ внутри чата**: для архитектора (GPT/Codex), для реализатора (Claude Code), для независимого аудитора (20 пунктов проверки, вердикты APPROVE / APPROVE WITH CHANGES / REBUILD).
6. **Content & Growth — общий департамент, не отдельная корпорация**: 7 функций (Content Director, Knowledge Miner, Researcher, Writer/Editor, Brand Voice, Distribution & Growth, Content Auditor); у каждого материала поля BRAND/AUDIENCE/PURPOSE/FUNNEL_STAGE/CTA/PRODUCT/RESULT.
7. **Два сервера**: казахстанский = AI Development Node (Codex Worker + Claude Worker + оркестратор + n8n), российский = Runtime/Production (пользователь `deploy-ai` без root, ограниченные sudo-команды деплоя, healthcheck, rollback). Связь — Tailscale/WireGuard. Деплой только через Git → тесты → review → staging → approval → production.
8. **Парная разработка Codex + Claude**: режимы PAIR / PARALLEL / COMPETE / REVIEW; над ними AI CTO/оркестратор; общение моделей только структурированными сообщениями, не свободным чатом.
9. **Model Board**: разные модели по ролям (стратегия, кодинг, аудит, дешёвая классификация); конфиденциальные данные — только в утверждённый контур, дешёвым/open-weight моделям — обезличенные задачи.
10. **Референсы высокомонетизированных AI-компаний** (цифры — заявления из чата, не проверены заново): Cursor (product-led, мгновенная ценность), Lovable (результат = готовый продукт, не код), Sierra (outcome-based pricing — плата за результат), Glean (context layer компании с правами доступа), Harvey (вертикальная глубина вместо универсальности → ВФОРУМЕ как «операционная система групп и сообществ»), ElevenLabs (технология → продукт → готовый бизнес-процесс), Cognition/Devin (режимы pair/delegate), Arena (внутренняя арена оценки моделей → Router распределяет работу по факту качества).
11. **Главный закон**: «Не создаём функцию, пока не понятно, какую дорогую работу она заменяет или какой новый доход создаёт».
12. **AI Corporate OS как переносимый продукт**: multi-tenant с первого дня, концепция Blueprint → Department → Agent → Skill → Workflow → Connector → Model, «компания как код» (company.yaml + агенты + workflow + коннекторы + политики), конструктор «Создать AI-компанию». Первая tenant — корпорация владельца; далее продукт можно разворачивать другим компаниям.
13. **Слой Decision Science** (по мотивам сериала «Что и требовалось доказать»): байесовское обновление вероятностей гипотез, теория графов для связей участников/групп (продуктовая функция ВФОРУМЕ), имитационное моделирование решений до траты денег, «византийская задача» для согласования разногласий агентов; роль Chief Decision Scientist с правом сказать «данных недостаточно».
14. **Стратегия при минимальном капитале** (оценки — расчёт ассистента чата): лестница «обучение собственников (деньги + лиды + research) → AI-внедрение компаниям (высокие чеки сейчас) → AI Corporate OS (будущий B2B-продукт)», ВФОРУМЕ — первый вертикальный SaaS. Правило R&D: «Сначала продажа. Потом код». Целевые чеки внедрения: диагностика 150–300 тыс. ₽, архитектура 300–700 тыс. ₽, внедрение 700 тыс.–3 млн ₽, поддержка 100–500 тыс. ₽/мес.
15. **Книжная база/доктрины**: Helmer «7 Powers», Rumelt, Gil, Cagan, Torres, Perri, Dunford, Fitzpatrick, Ramanujam/Tacke, «Accelerate», «Team Topologies», Kleppmann, Huyen «AI Engineering»; кейсы превращаются в формат PRINCIPLE / WHEN_TO_USE / WHEN_NOT_TO_USE / METRIC / DECISION_RULE.

### Связь с текущими наработками

- Конвергенция: единый task protocol, независимый проверяющий, журнал действий, human approval и «владелец над конвейером» уже частично реализованы в `10_corporation_repo` (workboard + ревью по SHA256) и пакетах отделов.
- Новое относительно собранного 23–26.10: Founder AI OS / AI Corporate OS как переносимый multi-tenant продукт; двухсерверная схема KZ-разработка ↔ RU-production с Tailscale и ограниченным `deploy-ai`; режимы парной разработки Codex+Claude; слой Decision Science; лестница монетизации «обучение → внедрение → продукт»; Content & Growth как общий департамент; Model Router и внутренняя арена моделей.
- Открытый вопрос: в чате фигурирует российский production-сервер — его наличие и параметры в собранных ранее материалах не подтверждены (известен только VPS Beget kazakhstan).
